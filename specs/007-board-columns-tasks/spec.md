# Feature Specification: Доска с колонками и задачами

**Feature Branch**: `007-board-columns-tasks`
**Created**: 2026-03-26
**Status**: Draft
**Input**: User description: "реализуем доску с колонками, на которой можно создавать и перемещать задачи"

## User Scenarios & Testing

### User Story 1 - Создание колонки на доске (Priority: P1)

Пользователь может создавать колонки на доске для организации задач.

**Why this priority**: Колонки — это основа Kanban-доски. Без колонок невозможно организовать задачи по статусам или категориям. Это базовая функция для работы с доской.

**Independent Test**: Пользователь может открыть доску, нажать "Добавить колонку", ввести название и создать колонку, которая отображается на доске.

**Acceptance Scenarios**:

1. **Given** пользователь открыл доску, **When** нажимает "Добавить колонку" и вводит название, **Then** колонка создаётся и отображается на доске
2. **Given** пользователь вводит название колонки (1-255 символов), **When** создаёт колонку, **Then** колонка сохраняется с указанным названием
3. **Given** пользователь не ввёл название колонки, **When** пытается создать колонку, **Then** система показывает ошибку валидации
4. **Given** пользователь создал несколько колонок, **When** открывает доску, **Then** видит все колонки в правильном порядке

---

### User Story 2 - Создание задачи в колонке (Priority: P1)

Пользователь может создавать задачи внутри колонки доски.

**Why this priority**: Задачи — это основная единица работы на доске. Возможность создавать задачи в колонках критична для использования доски.

**Independent Test**: Пользователь может открыть колонку, нажать "Добавить задачу", ввести название и создать задачу, которая отображается в колонке.

**Acceptance Scenarios**:

1. **Given** пользователь открыл доску с колонками, **When** нажимает "Добавить задачу" в колонке и вводит название, **Then** задача создаётся и отображается в колонке
2. **Given** пользователь вводит название задачи (1-255 символов), **When** создаёт задачу, **Then** задача сохраняется с указанным названием
3. **Given** пользователь вводит описание задачи (опционально), **When** создаёт задачу, **Then** описание сохраняется вместе с задачей
4. **Given** пользователь не ввёл название задачи, **When** пытается создать задачу, **Then** система показывает ошибку валидации
5. **Given** в колонке уже есть задачи, **When** создаётся новая задача, **Then** она добавляется в конец колонки

---

### User Story 3 - Перемещение задачи между колонками (Priority: P1)

Пользователь может перемещать задачи между колонками для изменения их статуса.

**Why this priority**: Перемещение задач между колонками — ключевая функция Kanban-доски. Позволяет отслеживать прогресс работы над задачами.

**Independent Test**: Пользователь может перетащить задачу из одной колонки в другую, и задача отображается в новой колонке.

**Acceptance Scenarios**:

1. **Given** задача находится в колонке "To Do", **When** пользователь перемещает задачу в колонку "In Progress", **Then** задача отображается в новой колонке
2. **Given** пользователь перемещает задачу, **When** операция завершается, **Then** позиция задачи в новой колонке устанавливается корректно
3. **Given** задача была перемещена, **When** пользователь обновляет страницу, **Then** задача остаётся в новой колонке
4. **Given** пользователь не имеет прав на редактирование доски, **When** пытается переместить задачу, **Then** система показывает ошибку доступа

---

### User Story 4 - Редактирование задачи (Priority: P2)

Пользователь может редактировать название и описание задачи.

**Why this priority**: Позволяет корректировать информацию о задаче в процессе работы. Важно для практического использования.

**Independent Test**: Пользователь может открыть задачу на редактирование, изменить название или описание и сохранить изменения.

**Acceptance Scenarios**:

1. **Given** задача существует, **When** пользователь редактирует название, **Then** изменения сохраняются
2. **Given** задача имеет описание, **When** пользователь обновляет описание, **Then** новое описание сохраняется
3. **Given** пользователь пытается установить пустое название, **When** сохраняет изменения, **Then** система показывает ошибку валидации
4. **Given** пользователь не имеет прав на редактирование, **When** пытается редактировать задачу, **Then** система показывает ошибку доступа

---

### User Story 5 - Удаление задачи (Priority: P2)

Пользователь может удалить задачу из колонки.

**Why this priority**: Важная функция управления задачами, но не критична для базового рабочего процесса.

**Independent Test**: Пользователь может удалить задачу, и она исчезает из колонки.

**Acceptance Scenarios**:

1. **Given** задача существует в колонке, **When** пользователь удаляет задачу, **Then** задача больше не отображается в колонке
2. **Given** задача была удалена, **When** пользователь обновляет страницу, **Then** задача остаётся удалённой
3. **Given** пользователь не имеет прав на удаление, **When** пытается удалить задачу, **Then** система показывает ошибку доступа

---

### User Story 6 - Переименование колонки (Priority: P2)

Пользователь может изменить название колонки.

**Why this priority**: Позволяет корректировать названия колонок для лучшего отражения workflow команды.

**Independent Test**: Пользователь может открыть колонку на редактирование, изменить название и сохранить изменения.

**Acceptance Scenarios**:

1. **Given** колонка существует, **When** пользователь редактирует название, **Then** изменения сохраняются
2. **Given** пользователь пытается установить пустое название, **When** сохраняет изменения, **Then** система показывает ошибку валидации
3. **Given** пользователь не имеет прав на редактирование, **When** пытается переименовать колонку, **Then** система показывает ошибку доступа

---

### User Story 7 - Удаление колонки (Priority: P3)

Пользователь может удалить колонку со всеми задачами.

**Why this priority**: Важная функция управления, но требует осторожности из-за удаления всех задач в колонке.

**Independent Test**: Пользователь может удалить колонку, после чего колонка и все её задачи исчезают.

**Acceptance Scenarios**:

1. **Given** колонка существует, **When** пользователь удаляет колонку, **Then** колонка и все задачи удаляются
2. **Given** пользователь удаляет колонку, **When** подтверждает удаление, **Then** система предупреждает о потере задач
3. **Given** пользователь не имеет прав на удаление, **When** пытается удалить колонку, **Then** система показывает ошибку доступа

---

### Edge Cases

- Что происходит, когда пользователь пытается создать колонку с пустым названием?
- Как система обрабатывает создание задачи с названием длиннее 255 символов?
- Что происходит при перемещении задачи в несуществующую колонку?
- Как система обрабатывает потерю соединения при создании/перемещении задачи?
- Что происходит при попытке доступа к несуществующей доске или колонке?
- Как обрабатывается ситуация когда токен аутентификации истёк во время работы с доской?
- Что происходит при удалении колонки — удаляются ли все задачи в ней?
- Как система обрабатывает одновременное перемещение одной задачи несколькими пользователями?

## Requirements

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставлять форму создания колонки с полем названия (1-255 символов)
- **FR-002**: Система ДОЛЖНА валидировать название колонки (обязательное поле, 1-255 символов)
- **FR-003**: Система ДОЛЖНА показывать ошибки валидации для названия колонки
- **FR-004**: Система ДОЛЖНА предоставлять форму создания задачи с полями: название, описание (опционально)
- **FR-005**: Система ДОЛЖНА валидировать название задачи (обязательное поле, 1-255 символов)
- **FR-006**: Система ДОЛЖНА валидировать описание задачи (опционально, 0-10000 символов)
- **FR-007**: Система ДОЛЖНА показывать ошибки валидации для полей задачи
- **FR-008**: Система ДОЛЖНА позволять перемещать задачи между колонками на доске
- **FR-009**: Система ДОЛЖНА сохранять позицию задачи в колонке после перемещения
- **FR-010**: Система ДОЛЖНА позволять редактировать название и описание задачи
- **FR-011**: Система ДОЛЖНА позволять удалять задачи из колонок
- **FR-012**: Система ДОЛЖНА позволять переименовывать колонки
- **FR-013**: Система ДОЛЖНА позволять удалять колонки со всеми задачами
- **FR-014**: Система ДОЛЖНА показывать подтверждение перед удалением колонки с задачами
- **FR-015**: Система ДОЛЖНА проверять права доступа перед созданием/редактированием/удалением задач и колонок
- **FR-016**: Система ДОЛЖНА отображать все колонки доски в правильном порядке
- **FR-017**: Система ДОЛЖНА отображать все задачи в колонке в правильном порядке
- **FR-018**: Система ДОЛЖНА показывать сообщение если в доске нет колонок
- **FR-019**: Система ДОЛЖНА показывать сообщение если в колонке нет задач

### Key Entities

- **Board (Доска)**: Основное рабочее пространство. Имеет название, описание, владельца, статус. Содержит колонки.
- **Column (Колонка)**: Контейнер для задач внутри доски. Имеет название, позицию в доске, дату создания. Содержит задачи.
- **Task (Задача)**: Единица работы в колонке. Имеет название, описание, позицию в колонке, исполнителя, статус удаления, даты создания и обновления.
- **BoardMember (Участник доски)**: Связь пользователя с доской. Определяет роль (owner/admin/member) и права доступа (read/write/delete).

## Success Criteria

### Measurable Outcomes

- **SC-001**: Пользователь может создать колонку менее чем за 10 секунд
- **SC-002**: Пользователь может создать задачу менее чем за 15 секунд
- **SC-003**: Пользователь может переместить задачу между колонками менее чем за 5 секунд
- **SC-004**: Доска с до 20 колонками и 100 задачами загружается менее чем за 2 секунды
- **SC-005**: 95% пользователей успешно создают первую задачу с первой попытки
- **SC-006**: 90% пользователей могут переместить задачу между колонками без обращения к документации
- **SC-007**: Время отклика на действия с задачами (создание/перемещение/редактирование) не превышает 1 секунды

## Assumptions

- Backend API для управления колонками и задачами уже реализован (003-task-boards-crud feature)
- API предоставляет endpoints для CRUD операций с колонками и задачами
- Пользователь аутентифицирован перед доступом к функциям управления доской (005-frontend-auth)
- JWT токен хранится в localStorage и автоматически прикрепляется к запросам
- Frontend использует React + TypeScript + Bootstrap 5 (из 005-frontend-auth)
- Пользователи имеют стабильное интернет-соединение для работы с веб-приложением
- Мобильная версия интерфейса адаптируется автоматически (responsive design)
- Язык интерфейса — русский (по умолчанию для проекта)
- Удаление колонки удаляет все задачи в ней (каскадное удаление)
- Перемещение задач реализовано через drag-and-drop или кнопки

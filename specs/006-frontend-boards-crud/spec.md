# Feature Specification: Создание и удаление досок на фронтенде

**Feature Branch**: `006-frontend-boards-crud`
**Created**: 2026-03-26
**Status**: Draft
**Input**: User description: "создание и удаление досок на фронтенде"

## Clarifications

### Session 2026-03-26

- Q: Где должна располагаться кнопка удаления доски? → A: В настройках/меню доски — меньше риск случайного удаления, требует осознанного действия
- Q: Как должен выглядеть интерфейс создания доски? → A: Модальное окно поверх главной страницы — быстро, не теряется контекст, проще реализовать
- Q: Как должен выглядеть диалог подтверждения удаления? → A: Модальное окно с кнопками "Отмена"/"Удалить" и требованием ввести название доски для подтверждения

## User Scenarios & Testing

### User Story 1 - Создание новой доски (Priority: P1)

Пользователь может создать новую доску с названием и описанием через модальное окно.

**Why this priority**: Это основная функция приложения. Без возможности создания досок приложение не имеет ценности. Это первый шаг в пользовательском пути после регистрации.

**Independent Test**: Пользователь может открыть модальное окно создания доски, заполнить название и описание, и создать доску, после чего перенаправляется на созданную доску.

**Acceptance Scenarios**:

1. **Given** пользователь аутентифицирован и находится на главной странице, **When** пользователь нажимает "Создать доску" и заполняет форму, **Then** доска создаётся и пользователь перенаправляется на неё
2. **Given** пользователь вводит название доски (1-255 символов), **When** создаёт доску, **Then** доска сохраняется с указанным названием
3. **Given** пользователь вводит описание (опционально), **When** создаёт доску, **Then** описание сохраняется вместе с доской
4. **Given** пользователь не ввёл название доски, **When** пытается создать доску, **Then** система показывает ошибку валидации
5. **Given** пользователь вводит название длиннее 255 символов, **When** пытается создать доску, **Then** система показывает ошибку валидации

---

### User Story 2 - Просмотр списка досок (Priority: P1)

Пользователь видит список всех досок, где он является владельцем или участником.

**Why this priority**: Пользователи должны видеть свои доски для быстрого доступа. Это основная навигационная точка приложения.

**Independent Test**: Пользователь открывает главную страницу и видит список своих досок с названиями и описаниями.

**Acceptance Scenarios**:

1. **Given** пользователь имеет несколько досок, **When** открывает главную страницу, **Then** видит список всех своих досок
2. **Given** доска имеет описание, **When** отображается в списке, **Then** описание показывается под названием
3. **Given** у пользователя нет досок, **When** открывает главную страницу, **Then** видит сообщение "У вас пока нет досок" и кнопку "Создать доску"
4. **Given** пользователь кликает на доску в списке, **When** переходит на доску, **Then** открывается детальная страница доски

---

### User Story 3 - Удаление доски (Priority: P2)

Владелец доски может удалить доску со всеми связанными данными. Кнопка удаления расположена в настройках/меню доски. Для подтверждения удаления требуется ввести название доски.

**Why this priority**: Важная функция управления, но не критична для базового рабочего процесса. Только владелец может удалять доски.

**Independent Test**: Владелец доски может удалить доску через диалог подтверждения с вводом названия, после чего доска исчезает из списка.

**Acceptance Scenarios**:

1. **Given** пользователь является владельцем доски, **When** удаляет доску, **Then** доска удаляется и пользователь перенаправляется на главную страницу
2. **Given** пользователь удаляет доску, **When** вводит название доски для подтверждения, **Then** все связанные данные (колонки, задачи, участники) удаляются
3. **Given** пользователь не является владельцем доски, **When** пытается удалить доску, **Then** система показывает ошибку доступа
4. **Given** пользователь нажал "Удалить", **When** вводит неправильное название доски, **Then** кнопка удаления неактивна

---

### User Story 4 - Редактирование доски (Priority: P2)

Владелец доски может изменить название и описание доски.

**Why this priority**: Позволяет корректировать информацию о доске. Важно для практического использования.

**Independent Test**: Владелец доски может открыть редактирование и изменить название или описание.

**Acceptance Scenarios**:

1. **Given** пользователь является владельцем доски, **When** редактирует название, **Then** изменения сохраняются
2. **Given** пользователь редактирует описание, **When** сохраняет изменения, **Then** новое описание сохраняется
3. **Given** пользователь не является владельцем, **When** пытается редактировать, **Then** система показывает ошибку доступа

---

### User Story 5 - Просмотр детальной информации о доске (Priority: P1)

Пользователь может открыть доску и видеть её содержимое с колонками и задачами.

**Why this priority**: Основная рабочая область приложения. Пользователи проводят большую часть времени в доске.

**Independent Test**: Пользователь открывает доску и видит колонки с задачами.

**Acceptance Scenarios**:

1. **Given** доска имеет колонки, **When** пользователь открывает доску, **Then** видит все колонки с задачами
2. **Given** доска не имеет колонок, **When** пользователь открывает доску, **Then** видит пустую доску с возможностью добавить колонку
3. **Given** пользователь не имеет доступа к доске, **When** пытается открыть доску, **Then** система показывает ошибку доступа

---

### Edge Cases

- Что происходит, когда пользователь пытается создать доску с пустым названием?
- Как система обрабатывает создание доски с названием длиннее 255 символов?
- Что происходит при попытке удалить доску без подтверждения?
- Как система обрабатывает потерю соединения при создании/удалении доски?
- Что происходит при попытке доступа к несуществующей доске?
- Как обрабатывается ситуация когда токен аутентификации истёк во время работы с доской?

## Requirements

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставлять форму создания доски с полями: название, описание (опционально)
- **FR-002**: Система ДОЛЖНА валидировать название доски (1-255 символов, обязательное поле)
- **FR-003**: Система ДОЛЖНА валидировать описание доски (0-10000 символов, опционально)
- **FR-004**: Система ДОЛЖНА показывать ошибки валидации для каждого поля формы
- **FR-005**: Система ДОЛЖНА показывать ошибку "Название уже используется" при создании доски с существующим названием (если применимо)
- **FR-006**: Система ДОЛЖНА отображать список досок пользователя на главной странице
- **FR-007**: Система ДОЛЖНА показывать название и описание для каждой доски в списке
- **FR-008**: Система ДОЛЖНА перенаправлять на созданную доску после успешного создания
- **FR-009**: Система ДОЛЖНА предоставлять кнопку/ссылку для удаления доски (только для владельца)
- **FR-010**: Система ДОЛЖНА показывать диалог подтверждения перед удалением доски
- **FR-011**: Система ДОЛЖНА перенаправлять на главную страницу после успешного удаления
- **FR-012**: Система ДОЛЖНА показывать ошибку доступа при попытке не-владельца удалить доску
- **FR-013**: Система ДОЛЖНА предоставлять форму редактирования доски для владельца
- **FR-014**: Система ДОЛЖНА отображать детальную страницу доски с колонками и задачами
- **FR-015**: Система ДОЛЖНА показывать сообщение "У вас пока нет досок" если у пользователя нет досок
- **FR-016**: Система ДОЛЖНА проверять права доступа перед открытием доски

### Key Entities

- **Board (Доска)**: Основное рабочее пространство. Имеет название (уникальное для пользователя), описание (опционально), владельца, статус (active/archived), дату создания.
- **BoardMember (Участник доски)**: Связь пользователя с доской. Определяет роль (owner/admin/member) и права доступа (read/write/delete).
- **Column (Колонка)**: Контейнер для задач внутри доски. Имеет название, позицию, дату создания.
- **Task (Задача)**: Единица работы в колонке. Имеет название, описание, позицию, исполнителя, статус удаления.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Пользователь может создать доску менее чем за 30 секунд
- **SC-002**: Список досок загружается менее чем за 1 секунду для пользователя с до 50 досками
- **SC-003**: 95% пользователей успешно создают доску с первой попытки
- **SC-004**: Время отклика на действия с досками (создание/удаление/редактирование) не превышает 2 секунд
- **SC-005**: Форма создания и редактирования корректно отображается на экранах от 320px до 1920px шириной
- **SC-006**: 90% пользователей могут найти и использовать функцию удаления доски без обращения к документации

## Assumptions

- Backend API для управления досками уже реализован (003-task-boards-crud feature)
- API предоставляет endpoints: POST /api/boards, GET /api/boards, GET /api/boards/{id}, PUT /api/boards/{id}, DELETE /api/boards/{id}
- Пользователь аутентифицирован перед доступом к функциям управления досками (005-frontend-auth)
- JWT токен хранится в localStorage и автоматически прикрепляется к запросам
- Frontend использует React + TypeScript + Bootstrap 5 (из 005-frontend-auth)
- Пользователи имеют стабильное интернет-соединение для работы с веб-приложением
- Мобильная версия интерфейса адаптируется автоматически (responsive design)
- Язык интерфейса — русский (по умолчанию для проекта)
- Удаление доски является окончательным (нет функции восстановления)
